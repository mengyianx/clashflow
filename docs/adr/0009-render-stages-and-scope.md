# 配置生成的层次与作用域：四段式、按配置的组与提供者、Age 交给内核

状态：已接受（2026-11-06）；补充 ADR-0004 的渲染段落与 ADR-0007 的管理面。

核对 OpenClash 的 `yml_*` 脚本后可以确认：它的配置生成不是一次合并，而是四段串行改写；策略组、节点、提供者也**不属于全局**，而是挂在某一份配置文件上，另有「Use For All Config File」开关。我们此前的 `render(source, overlay)` 只覆盖了第一段的一部分，且把组与提供者当成全局对象——两处都要修正。

## 决定

- **四段式生成**，每段是纯函数，输入输出都是完整 mihomo YAML：
  1. **键合并**：Overlay 的网关与数据面键（TUN、DNS 基础、端口族、流量控制、日志）覆盖源配置同名字段。
  2. **规则注入**：自定义规则列表（对应 `custom_rules.list` 与 `custom_rules_2.list`）插到 `rules` 顶部，规则提供者与 `mrs`/`dat` 来源在此解析。
  3. **域名与嗅探**：sniffer 配置、hosts、节点命名策略。
  4. **对象增删改**：策略组、节点、提供者的增删改。
- **作用域**：第 4 段里的策略组、节点、提供者**属于某一份源配置**，并提供「一键应用到全部配置」；Overlay（第 1 段）仍是全局一份。理由：订阅各自带来的组与节点形状不同，全局一份必然互相污染；而 TUN/DNS 这类网关参数与配置无关。
- **失败定位**：任何一段失败都仍归入 `render-failed`，但错误信息必须带段名（例如「规则注入：第 3 条规则的策略组不存在」），否则排障要读整份 YAML。
- **Age 交给内核**：mihomo 支持 `age-secret-key`（配置键与 `-age-secret-key` 命令行参数），并提供 `mihomo age keygen` / `mihomo age convert`。面板只存 key、把 key 传给 `mihomo -t` 与内核进程、把两个子命令接成按钮，不实现任何解密逻辑。因此 Age 从「2.1 自研」提前为「2.0 直接支持」。

## 后果

- `render` 从单函数变成四段管线，测试也要按段写：每段的输入输出都是完整 YAML，段间可独立断言。
- 数据模型多一层「组/节点/提供者属于哪份配置」；「应用到全部」是批量写，失败要能回滚到写之前的全部配置。
- Age 不再有密码学面，只剩「key 存哪里、怎么传」。key 与订阅 URL 同级敏感（明文落 `/data`），沿用现有取舍。
- 出口 IP 检测会向外发请求：只使用可配置端点，默认关闭，开启时在诊断包里记下所用端点。

## 备选方案（未采用）

- **单步 merge**：实现简单，但每加一项注入都在同一个函数里长，且失败无法定位到阶段。
- **组/提供者全局一份**：省掉作用域概念，但订阅 A 的组会污染订阅 B——多订阅是本项目的主场景，不可接受。
- **自己实现 Age 解密**：多一个密码学依赖与一类错误，而内核已经提供，纯属重复劳动。
