# 取代 OpenClash：对齐范围、订阅转换与许可

状态：已接受（2026-11-06）；修订 ADR-0004 的键集与「不做」边界，不改 ADR-0005 / 0006 的结论。

目标从「自用的家用网关面板」改成「完全取代使用者现有的 OpenClash」。前几轮按最小可用划的边界不够：订阅转换、覆写全量、节点/策略组/提供者管理、内核与规则集管理、统计与诊断都在实际使用中，缺一项就还得留着 OpenClash。因此重新划线，并按可验证的节奏拆成 2.0 / 2.1。

## 决定

- **拓扑**：OpenWrt 保留做路由与 DHCP；ClashFlow 主机作为旁路由网关，LAN 设备的网关与 DNS 指向它。不把容器装到路由器上，也不替换主路由。
- **订阅**：仍是一份订阅 ↔ 一份源配置；一条订阅可含**多个 URL**，合并发生在 subconverter 的参数层，不引入「一份配置挂 N 个订阅」的模型。
- **订阅转换**：镜像内置 subconverter 二进制（pin 版本），常驻子进程，只监听 `127.0.0.1`，由面板生成其配置；输入支持分享链接、base64 列表与完整 YAML，输出必须是完整 mihomo YAML，再进渲染 → 校验 → 原子写。
- **覆写**：键组扩到 OpenClash 的完整集合（general / DNS / rules / proxy-groups / proxy-providers / rule-providers 等），分批移植；ADR-0004 的「面板恒胜」与「渲染在校验之前」不变。
- **管理面**：提供者与策略组用结构化表单，节点列表只读（来自订阅），自定义节点逐条表单；不做节点延迟/筛选器的可视化编排。
- **内核**：仍只 mihomo（多版本）；不引入 smart/premium，也不复制它们的 CLI 与校验差异。
- **看门狗**：进程监控 + TUN 设备/路由 + 出网探测 + DNS 解析探测，连续失败重启内核；不移植 OpenClash 的场景脚本、节点自动切换与定时重启。
- **迁移**：只导入 OpenClash 的最终 `config.yaml` 作为源配置；订阅与覆写由用户在新面板重建（导入器不做 uci 逆向映射）。
- **许可**：ClashFlow 采用 MIT 并加 `THIRD_PARTY_NOTICES.md`。OpenClash（MIT）移植处保留声明；移植是**改写**而非逐字节复制（Lua/shell → Python/TypeScript）。subconverter 是唯一 GPL-3.0 依赖，以独立进程分发，镜像需附许可文本与源码获取途径。
- **交付切分**：2.0 = 渲染层 + host 网络/TUN + 订阅转换（能真正接管日常流量）；2.1 = 覆写全量 + 节点/组/提供者管理 + 内核多版本 + 看门狗 + 统计与诊断。每版都能独立上线验证。

## 后果

- 镜像从单进程变成双进程：subconverter 崩溃不能拖垮面板与内核，需要独立守护与状态展示；转换失败是新失败类别 `conversion-failed`。
- 旁路由拓扑是部署前提：LAN 设备的网关与 DNS 不指向 ClashFlow 主机时，TUN 收不到流量。这靠文档与诊断页的只读快照表达，代码无法替用户改。
- 「取代」的判定是使用者的判断而非代码承诺；对照表与迁移说明是唯一能给出的东西。
- 引入一个 GPL-3.0 依赖后，镜像分发方式（推 ghcr）必须同时附带源码获取途径，否则合规不成立。

## 备选方案（未采用）

- **外部 subconverter 服务**：零 GPL 义务，但多一个必须存在的组件和一类失败模式，与「一条 docker run 得到可用网关」冲突。
- **自研链接解析**：可控、无外部依赖，但协议面（hysteria2 / tuic / anytls / mieru …）会持续落后，等于长期维护一个二流转换器。
- **源配置可挂 N 个订阅**：表达力更强，但刷新语义、冲突归属与迁移都会变复杂；subconverter 层面合并已经覆盖实际需求。
- **支持多核心**：CLI、校验与 API 都不同，等于再写一条 apply 管线；使用者在用的是 mihomo。
- **一次性发 2.0 对齐全部**：版本号干净，但周期内没有可真实使用的中间态，出问题无法归因。
